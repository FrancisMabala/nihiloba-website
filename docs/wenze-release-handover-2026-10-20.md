# Wenze release acceptance and handover — WNZ-14

## Released scope

WNZ-01 through WNZ-11 are deployed. The authoritative Implementation Tracker retains each batch's commits, independent remote SHA checks, migration evidence and Render observations. This handover does not certify the blocked fiscal integration or untested physical devices.

The work separates commercial receipts from fiscal invoices; adds truthful seller payment preferences and fulfillment estimates; records order progress and historical delivery promises; provides authenticated web checkout and buyer updates; enforces the real inbound WhatsApp service window; adds category guidance, public condition and complete-catalog discovery filters; and brings the seller tools to the Organization workspace.

The existing order, stock, checkout, receipt and inbox services remain the source of truth. This avoids a second order engine and preserves historical snapshots, retry protection and separate CDF/USD totals. Payment preferences do not enable payment processing. Category guidance preserves the existing single stock-bearing variant dimension. Organization presentation reuses the Personal workflows while binding requests to the selected Organization and retaining backend authorization.

## Remaining acceptance and dependencies

WNZ-12 and WNZ-13 remain blocked on verified applicable DGI technical requirements, an approved integration route, test access and seller tax-profile requirements. No fiscal identifiers, default tax obligations or authenticated fiscal issuance have been invented. Unsupported payment methods remain unavailable for collection.

Physical thermal-printer scaling/legibility, actual barcode scanners, device camera scanning and native phone file sharing still require device acceptance. Full manual keyboard/focus, partial-upload recovery and every seller editor's unsaved-change journey are not established by the mobile navigation suite. The Seller audit retains these limits rather than marking all screens fully verified.

An additional unchanged-backend regression run produced 25 passes and four failures: three Organization grant fixtures omit current operational onboarding fields, and one reporting assertion expects Pro grant revocation to override the enabled testing-period access. These failures remain open; they were not bypassed or counted as passing. The separate 47-test affected-journey run above passed. No new migration or environment setting is required for WNZ-11 or this documentation-only handover. Previously authorized migrations through 0187 are recorded in the tracker. This release does not authorize further production database operations.
