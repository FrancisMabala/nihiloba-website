# Personal Wenze: first product

After a successful shop creation, the seller can open a product draft for that shop or enter its management dashboard. Refreshing returns to the shop without repeating the creation request. Product drafts and their ordered photo references stay in memory while moving between steps or switching languages. Reloading a product draft is not a recovery mechanism.

The options editor starts in single-version mode (a blank quantity means untracked). For several versions, select a colour or other secondary attribute, then choose a size or primary attribute to create that exact row. Select another secondary value to offer only the currently selected primary value in that version. Edit a row’s secondary selection or remove that row without redistributing other stock. In Other options, change the primary attribute before adding rows, or select an existing primary value for the next pairing. Each tracked version needs an integer quantity, including zero for sold-out versions. Up to 20 versions are supported.

The authorized personal Pro workspace calculates the private unit result in the selling currency. Cost is never included in the product create payload. Product creation reuses the existing draft publication identity and request retry key; stock is part of the same publication. Confirmation uses the management API’s saved photos, available quantities and option attributes. If a subsequent private-cost write fails, retry only the outstanding targets. Labels use the existing generation, print and PDF controls independently.

Browser acceptance coverage: `tests/browser/wenze-creation.browser.ts` uses the running Next application with controlled management API responses, including a lost response after saving. Set `WENZE_CREATION_EVIDENCE` to a local output folder with four seller test uploads named `upload-0.png` through `upload-3.png` to capture the reference journey; without it the suite uses its existing repository image fixture. No production data is needed.
