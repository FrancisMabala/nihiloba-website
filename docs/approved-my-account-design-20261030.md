# Approved My Account design — 30 October 2026

Scope: `/shida/space?view=settings` and its supported EN/FR/LN/SW routes. This is a presentation change, with one verified frontend reconciliation fix. No backend, API contract, migration, dependency, production configuration, notification policy or WhatsApp template change.

## Implementation

- `account-settings-design.css`: page-scoped card widths, compact rows, forest-green/cream palette, restrained borders, serif headings, mobile stacking and focus/touch targets. The shared header, footer and other My Space pages retain their design.
- `personal-profile-settings.tsx`: edit icon, masked verified phone badge and localized country names. Existing revision-protected profile save, error handling and Cancel remain.
- `account-setting.tsx`: reusable native, keyboard-accessible disclosures, icons, chevrons and Cancel with focus return. A shared native details name makes the security and deletion disclosures mutually exclusive; all start closed.
- `account-security.tsx` / `optional-recovery-methods.tsx`: concise localized introductions, truthful backend-derived statuses and existing forms. Cancel clears local draft/verification fields where appropriate. The 24-hour activation notice is presented once above the rows; action-specific requirements and security warnings remain in the relevant forms.
- `account-space-icon.tsx` / `account-design-copy.ts`: reusable line icons and localized copy. Country display uses `Intl.DisplayNames`, falling back to the stored code when unavailable.
- `account-space.tsx`: settings-only styling, removes the redundant in-page language selector (the existing header language control remains), and assigns different React keys to profile and security. The prior identical sibling keys could leave a duplicate profile editor after a successful save/session refresh; the browser save test reproduces and guards this defect.
- Danger zone separates deletion from lost-phone protection. Opening a row performs no sensitive action. Deletion still requires eligibility review, explicit confirmation and authorization; lost-phone reporting retains its existing route.

## Preserved endpoints and channel behavior

Profile reads/writes use `/api/shida/personal/security/profile/`. Security overview, passkeys, email verification/proof, secondary recovery methods, primary phone replacement, session revocation and deletion retain their existing `/api/shida/personal/security/` routes and authorization logic. WhatsApp sign-in and both-number replacement proofs are unchanged. No new notification or conversation behavior is introduced. Urgent WhatsApp templates and the existing response-time measurements are unchanged.

## Validation and visual evidence

Build, TypeScript, targeted ESLint, staged secret scan and diff checks passed. All 34 gateway/navigation unit tests and 35 focused browser checks passed (33 in the account-design suite, plus two existing profile/status regressions). `playwright.account-design.config.ts` runs the focused visual/interaction checks and existing security/account regressions: four languages at 390px and 1440px, equal card widths, no horizontal overflow, keyboard accordion behavior, one open row, Cancel/focus reset, no writes on expansion, successful revision-based profile save, failed/stalled reads and saves, passkey enrollment with a virtual authenticator, email proof, and signed-out recovery.

Visual review uses the actual production build with synthetic account responses, never a real recovery credential. Desktop/mobile and expanded screenshots are generated by `account-design.browser.ts` using `ACCOUNT_DESIGN_EVIDENCE_DIR`. The rendered result was compared with the user-supplied reference and the card/row spacing tightened after the first pass. Local browser inspection independently checked the real rendered settings page.

Intentional differences: shared marketplace header/footer and existing mobile navigation are retained; minimum 44px controls and explicit field labels improve usability; country names replace raw country codes; the Danger zone explains lost-phone protection separately from permanent deletion. Demo identity/phone values are synthetic. Human review of LN/SW wording remains advisable.
